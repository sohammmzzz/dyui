=== S-0002
--- user
Sto integrando DyUI nel nostro tracker di contratti. Come si fa un grafico a barre impilate (stacked bar)? Ho due serie su lun e mar: "Nuovi" con 4 e 6, "Di ritorno" con 3 e 5. E come aggiungo una badge accanto per etichettarlo, con quali colori?
--- reference
Ecco un esempio di stacked bar con due serie, insieme a una badge per etichettarlo.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"chart\",\"kind\":\"bar\",\"labels\":[\"Lun\",\"Mar\"],\"series\":[{\"name\":\"Nuovi\",\"data\":[4,6]},{\"name\":\"Di ritorno\",\"data\":[3,5]}],\"stacked\":true}\n{\"ui\":\"badges\",\"items\":[{\"label\":\"Stacked bar\",\"color\":\"accent\"}]}"}
```
Il grafico impilato è un chart con kind bar e stacked true, dove ogni serie diventa un segmento. La badge richiede solo items, e ogni color può essere gray, accent, green, amber, red, blue o violet.

=== S-0006
--- user
quick q: when I show a pick-one question about vehicle class (Compact, SUV, Van), how does the answer get back to me? and what props can I set on it?
--- reference
A choice component sends the user's pick back as an action message, and here is one for vehicle class.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"choice\",\"question\":\"Which vehicle class?\",\"options\":[\"Compact\",\"SUV\",\"Van\"],\"multiple\":false,\"allow_other\":true,\"action\":\"pick_vehicle_class\",\"submit_label\":\"Confirm\"}"}
```
Only question and options are required; multiple, allow_other, action and submit_label are optional. When the user submits, you receive `[action:pick_vehicle_class]` followed by JSON with a `selected` array, plus an `other` field if they typed their own answer.

=== S-0005
--- user
how do i ask the user to confirm deleting plot B-12 and get the answer back?
--- reference
Use a confirm component with an action name and the plot in its data, as in this example.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"confirm\",\"title\":\"Delete plot B-12?\",\"text\":\"This removes the plot record permanently.\",\"confirm_label\":\"Delete\",\"cancel_label\":\"Keep it\",\"action\":\"delete_plot\",\"data\":{\"plot\":\"B-12\"},\"danger\":true}"}
```
Only title is required. The user's choice returns as `[action:delete_plot]` with your data plus a confirmed flag, so you get `{"plot":"B-12","confirmed":true}` or the same with false.

hey, if I show a stat for 3 bookings today, will tapping it fire an action back to you?
--- reference
A stat is display-only, so here is the booking number as one.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"stat\",\"label\":\"Bookings today\",\"value\":3}"}
```
It has no action prop: only label and value are required, with unit, delta, trend and help optional. Components such as buttons, confirm, form, choice and rating send `[action:<name>]` plus JSON back, while quick_replies simply arrive as a plain user message.

--- reference
For shares of a whole, use a chart with kind donut or pie, and a stat for the single largest share; both appear below.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"chart\",\"kind\":\"donut\",\"labels\":[\"API\",\"Web\",\"Batch\"],\"series\":[{\"name\":\"Traffic share\",\"data\":[62,28,10]}],\"title\":\"Request traffic\"}\n{\"ui\":\"stat\",\"label\":\"API share\",\"value\":\"62%\"}"}
```

A donut or pie works best with at most six slices, while a stat takes label and value as its required props. Use the stat alone when only one share matters.

=== S-0004
--- user
whats the difference between quick replies and buttons? and where do badges fit, like tagging my tomatoes "Ready" and basil "Needs water"
--- reference
Quick replies and buttons differ in how the answer comes back, and this example puts all three side by side.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"badges\",\"items\":[{\"label\":\"Tomatoes: Ready\",\"color\":\"green\"},{\"label\":\"Basil: Needs water\",\"color\":\"amber\"}]}\n{\"ui\":\"quick_replies\",\"options\":[\"Watering schedule\",\"Soil tips\"]}\n{\"ui\":\"buttons\",\"items\":[{\"label\":\"Mark watered\",\"action\":\"mark_watered\"}]}"}
```
Tapping a quick reply arrives as a plain user message, while a button sends `[action:mark_watered]` with JSON data. Badges are only labels with a color (gray, accent, green, amber, red, blue or violet), so they trigger nothing.
--- derived
