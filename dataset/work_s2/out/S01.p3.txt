=== S-0008
--- user
Kindly list the props of the stat component, using a "Gold sink" figure of 1200 with a delta of +8% as the example.
--- reference
Here is a stat that uses every prop, built from your gold sink figure.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"stat\",\"label\":\"Gold sink\",\"value\":1200,\"unit\":\"gold\",\"delta\":\"+8%\",\"trend\":\"up\",\"help\":\"Gold removed from the economy\"}"}
```
Stat requires label and value; unit, delta, trend and help are optional. Trend is one of up, down or flat.

=== S-0017
--- user
When should I use confirm rather than quick replies or buttons? Our example is cancelling the Lisbon trip.
--- reference
Use confirm when an action needs explicit approval first, such as cancelling the Lisbon trip.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"confirm\",\"title\":\"Cancel the Lisbon trip?\",\"text\":\"The booking will be released.\",\"confirm_label\":\"Cancel trip\",\"cancel_label\":\"Keep it\",\"action\":\"cancel_trip\",\"data\":{\"trip\":\"Lisbon\"},\"danger\":true}"}
```
Confirm, like buttons, sends [action:<name>] {json} back to me, while quick_replies arrive as plain user text. Only title is required on confirm.
--- derived


=== S-0026
--- user
choice vs quick replies, whats the difference? e.g. picking a pickup window, morning or afternoon
--- reference
Choice is a question with fixed options that returns an action message, as in this pickup example.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"choice\",\"question\":\"Which pickup window works?\",\"options\":[\"Morning\",\"Afternoon\"],\"action\":\"pick_window\"}"}
```
Choice sends [action:<name>] {json} with the selected options, whereas quick_replies arrive as a plain user message with no action.

=== S-0005
--- user
Are badges clickable like quick replies or buttons? We want to tag seats in the box office as Sold out and Few left, and I'd like to know what a badge can carry.
--- reference
Badges are labels only and carry no action, as in this example for your seat tags.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"badges\",\"items\":[{\"label\":\"Sold out\",\"color\":\"red\"},{\"label\":\"Few left\",\"color\":\"amber\"}]}"}
```
Each badge needs a label, and color is optional: gray, accent, green, amber, red, blue or violet. For something tappable, buttons send an action and quick_replies arrive as plain user text.

=== S-0012
--- user
Is timeline suitable for presenting the share of bookings per region: Europe 50, Asia 30, Americas 20?
--- reference
No, timeline shows events in order; shares of a whole belong in a chart with kind donut or pie.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"chart\",\"kind\":\"donut\",\"labels\":[\"Europe\",\"Asia\",\"Americas\"],\"series\":[{\"name\":\"Bookings\",\"data\":[50,30,20]}],\"title\":\"Bookings by region\"}"}
```
Timeline requires only items, and each item needs a title, with time, text and status (done, active or pending) optional.
--- derived
