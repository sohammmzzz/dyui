=== S-0002
--- user
Does the plan component send anything back when clicked? How does the action roundtrip work?
--- reference
The plan component has no action prop, so it only displays status; buttons are the usual way to send an action back, shown here next to a plan.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"plan\",\"title\":\"Claim steps\",\"items\":[{\"title\":\"Photos received\",\"status\":\"done\"},{\"title\":\"Review\",\"status\":\"active\"}]}\n{\"ui\":\"buttons\",\"items\":[{\"label\":\"Next\",\"action\":\"next_step\",\"style\":\"primary\"}]}"}
```
Buttons, confirm, form, choice and rating send an action message of the form [action:<name>] {json} back to me, while quick_replies arrive as plain user text.

=== S-0020
--- user
Could you explain how a confirm component returns the user's decision to you? I am wiring it into our event handler, for example restarting server eu-1.
--- reference
A confirm returns the decision as an action message, built from its action name and data.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"confirm\",\"title\":\"Restart the event server?\",\"text\":\"Players will be disconnected.\",\"confirm_label\":\"Restart\",\"cancel_label\":\"Cancel\",\"action\":\"restart_event\",\"data\":{\"server\":\"eu-1\"},\"danger\":true}"}
```
When the user chooses, I receive [action:restart_event] with the data plus the confirmed flag. Buttons, form, choice and rating use the same action pattern, while quick_replies come back as plain text.

=== S-0030
--- user
timeline: which props are required?
--- reference
Only items is required on a timeline, as in this minimal example.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"timeline\",\"items\":[{\"title\":\"Pledge received\",\"time\":\"Mon\",\"text\":\"Online donation\",\"status\":\"done\"},{\"title\":\"Receipt sent\",\"status\":\"active\"}]}"}
```
Inside each item only title is required, while time, text and status are optional, and status is one of done, active or pending.

=== S-0011
--- user
How do I get a stacked bar? Two series, workshops and talks: Mon 4 and 3, Tue 6 and 5.
--- reference
A stacked bar is a chart with kind bar, one series per part, and stacked set to true.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"chart\",\"kind\":\"bar\",\"labels\":[\"Mon\",\"Tue\"],\"series\":[{\"name\":\"Workshops\",\"data\":[4,6]},{\"name\":\"Talks\",\"data\":[3,5]}],\"stacked\":true}"}
```
Each series becomes one stacked segment per label, so the two series pile up within every day.

=== S-0028
--- user
Would a rating component be appropriate for showing the shares of total giving, or is there a better choice? Individuals 60, corporate 30, foundations 10.
--- reference
No, rating asks the user for a score; shares of a whole belong in a chart with kind donut or pie.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"chart\",\"kind\":\"donut\",\"labels\":[\"Individuals\",\"Corporate\",\"Foundations\"],\"series\":[{\"name\":\"Giving\",\"data\":[60,30,10]}],\"title\":\"Giving by donor type\"}"}
```
Use donut or pie for a handful of slices. Rating itself has only optional props: label, max, style (stars or thumbs) and action.

=== S-0021
--- user
Please list the properties of the chart component and indicate which are required. For an example, use tickets per day: Mon 12, Tue 30, Wed 21.
--- reference
Here is a chart that uses every prop, based on your tickets-per-day figures.
```dyui
{"ui":"code","language":"json","code":"{\"ui\":\"chart\",\"kind\":\"bar\",\"labels\":[\"Mon\",\"Tue\",\"Wed\"],\"series\":[{\"name\":\"Tickets\",\"data\":[12,30,21]}],\"title\":\"Tickets per day\",\"unit\":\"tickets\",\"stacked\":false}"}
```
The required props are kind and series; labels, title, unit and stacked are optional. Kind must be one of bar, line, area, pie, donut or scatter.
