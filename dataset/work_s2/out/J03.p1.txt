=== J-0027
--- user
oauth refresh token - what's it for?
--- reference
A refresh token lets an app obtain a new access token after the old one expires, without making the user sign in again. Access tokens stay short-lived for safety, while the refresh token is stored more carefully and can be revoked if it leaks.

=== J-0032
--- user
We run nightly backups of our customer records, but nobody has ever tried restoring one. Can you explain why testing backups matters?
--- reference
A backup is only useful if it can actually be restored, and problems like corrupted files, missing data or an outdated restore procedure usually show up only when you try. Testing on a schedule tells you how long recovery really takes and whether the team knows the steps, so nobody is learning them in the middle of an outage.
--- derived

--- reference
A redeploy takes time and carries risk for the whole app, while flipping a flag is instant and touches only that one feature. It also lets you switch a broken feature off right away.

=== J-0031
--- user
I'm writing a one-off script to rename a bunch of files in my training-log folder. Is it worth writing tests for a throwaway script?
--- reference
Usually not full tests: if you will run it once and can check the result by eye, your time is better spent elsewhere. The exception is a script that deletes or overwrites files, where a dry-run mode or a trial on a copy of the folder is cheap insurance.
--- derived

what happens when you type a url in the browser? short version
--- reference
The browser looks up the site's IP address through DNS, opens a connection (with TLS for HTTPS) and sends an HTTP request. The server returns HTML, and the browser fetches the linked files and renders the page.

=== J-0012
--- user
rate limiter, how does it work, few sentences
--- reference
It counts requests per client over a time window and blocks or delays those beyond a set limit. That protects a system from overload and abuse, for example a booking form being hit by a script. Common designs are the fixed window and the token bucket.
--- derived

=== J-0090
--- user
Our owner keeps mixing up MRR and ARR in the delivery-subscription report. What exactly is the difference between the two?
--- reference
MRR is monthly recurring revenue: the predictable subscription income you expect in a single month. ARR is annual recurring revenue, usually MRR scaled up to a full year, so it describes the same revenue base as a larger number.
--- derived

=== J-0082

Estamos montando um painel interno de contratos que só funciona dentro da rede da empresa. É necessário usar HTTPS mesmo assim?
--- reference
Sim, é recomendável. O HTTPS impede que credenciais e dados dos contratos sejam lidos ou alterados por quem estiver na mesma rede, e redes internas também podem ter máquinas comprometidas. Hoje o custo de configurar certificados é baixo.
